# خطة الاختبار التكاملي الشامل — نظام الدعم الذكي (متجر النور)

الهدف: التأكد إن كل الميزات السبعة شغالة **مع بعض** في جلسة واحدة متصلة، مش كل واحدة لوحدها. اتبع الترتيب ده بالظبط.

---

## المرحلة 0: الإعداد قبل الاختبار

### متغيرات البيئة المطلوبة (جهزها قبل التشغيل):
```bash
export ADMIN_TOKEN="ضع_توكن_قوي_هنا"
export ENABLE_LLM="false"          # هنبدأ false وبعدين نجربها true
export OLLAMA_HOST="http://localhost:11434"
export OLLAMA_MODEL="qwen2.5:3b"
export TENANT_ID="default"
export TELEGRAM_BOT_TOKEN=""       # سيبه فاضي لحد المرحلة 7
```

### خطوات:
- [ ] شغّل `python seed.py --force` وتأكد من ظهور رسالة نجاح توليد التذاكر التجريبية.
- [ ] شغّل السيرفر (`python app.py`) وراجع بانر الإقلاع: هل ظهر فيه التوكن (لو معملتش export لـ ADMIN_TOKEN)، اسم الـ Tenant، وحالة Telegram (متوقع "غير مُفعّل")؟
- [ ] افتح `http://localhost:9090/dashboard` وتأكد إن شاشة تسجيل الدخول ظهرت **قبل** أي بيانات.

## المرحلة 1: اختبار الحماية (Auth)

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1.1 | افتح `/api/stats` مباشرة في المتصفح بدون تسجيل دخول | `401 unauthorized` |
| 1.2 | سجّل دخول في الداشبورد بتوكن غلط | رسالة خطأ، مايدخلش |
| 1.3 | سجّل دخول بالتوكن الصحيح | الداشبورد يفتح ويعرض بيانات `seed.py` |
| 1.4 | اعمل refresh للصفحة بعد الدخول | يفضل مسجل دخول (sessionStorage شغال) |
| 1.5 | افتح تاب متصفح جديد (نافذة عادية جديدة) على نفس الرابط | يطلب تسجيل دخول تاني (sessionStorage مش localStorage) |

## المرحلة 2: اختبار الشات — الوضع الاستخراجي (`ENABLE_LLM=false`)

استخدم ملف `test_questions_dataset.md` المرفق. جرب **كل** الأسئلة من غير تفعيل LLM، وسجل في عمود "النتيجة الفعلية" هل طابقت المتوقع.

- [ ] الأسئلة الواضحة (شحن، دفع، استرجاع) رجعت `resolved` بإجابة مقتطعة من المستندات مباشرة.
- [ ] الأسئلة الغاضبة رجعت `priority` أو `escalated` مع اعتذار.
- [ ] الأسئلة الغامضة/خارج النطاق رجعت `escalated`.

## المرحلة 3: نفس الأسئلة مع تفعيل LLM (`ENABLE_LLM=true`)

```bash
export ENABLE_LLM="true"
```
تأكد إن Ollama شغال محلياً (`ollama run qwen2.5:3b` في تاب تاني، أو تأكد إنه service شغال).

- [ ] أعد نفس الـ 20+ سؤال. الإجابات المفروض تبقى مصاغة بأسلوب طبيعي (مش مقتطعة حرفياً) لكن **نفس حالة resolved/escalated/priority** بالظبط زي الوضع الاستخراجي (المنطق ده لازم يفضل ثابت، بس الصياغة اللي بتتغير).
- [ ] جرب سؤالين متتاليين بنفس `session_id` (استخدم نفس القيمة يدوياً في الطلب لو بتختبر عبر curl، أو استمر في نفس نافذة الشات لو فيها حفظ session تلقائي) وتأكد إن السؤال التاني فهم إشارة زي "وهل متاح منه لون أسود؟" بعد سؤال عن منتج معين.
- [ ] أوقف Ollama يدوياً وجرب سؤال تاني — لازم يرجع النظام لوضع extractive تلقائياً من غير كراش (اختبار الـ fallback الحقيقي).

## المرحلة 4: اختبار رفع الملفات

- [ ] من الداشبورد، اسحب وأفلت ملف `.txt` واحد صالح → يتفهرس بنجاح ويظهر في `total_chunks`.
- [ ] ارفع حزمة فيها ملفين صالحين + ملف بصيغة `.xyz` غير مدعومة → **الطلب كله يترفض** (400) ومفيش أي ملف اتفهرس (اختبار الـ atomicity اللي اتصلح).
- [ ] ارفع ملف `.docx` حقيقي فيه فقرة أو اتنين → يتفهرس بنجاح ويظهر محتواه في نتائج البحث.
- [ ] اسأل سؤال من محتوى الملف اللي رفعته لتوك، وتأكد إن الإجابة بتجيب من الملف الجديد.

## المرحلة 5: اختبار عزل الـ Tenant

```bash
# في تاب تاني، شغل نسخة تانية من السيرفر على بورت مختلف
export TENANT_ID="client_test"
python app.py --port 9091   # عدّل حسب طريقة تمرير البورت في مشروعك
```

- [ ] ابعت تذكرة على `client_test` (بورت 9091).
- [ ] راجع الداشبورد بتاع `default` (بورت 9090) وتأكد إن التذكرة **مش ظاهرة** فيه.
- [ ] راجع الداشبورد بتاع `client_test` وتأكد إنها ظاهرة بس عنده.
- [ ] تأكد إن `data/tenants/client_test/` اتبنى منفصل تماماً عن `data/tenants/default/`.

## المرحلة 6: اختبار ذاكرة المحادثة عبر جلسات متعددة

- [ ] افتح جلستين مختلفتين (`session_id` مختلف) وابعت أسئلة مختلفة في كل واحدة.
- [ ] تأكد إن سياق جلسة معينة **مش بيتسرب** للتانية (اسأل في الجلسة التانية سؤال بضمير زي "وهو ده كام؟" من غير سياق سابق فيها — المفروض النظام يتوه أو يطلب توضيح، مش يرد بمعلومة من الجلسة التانية).

## المرحلة 7: اختبار Telegram (لو عندك بوت تجريبي جاهز)

```bash
export TELEGRAM_BOT_TOKEN="التوكن الحقيقي بتاع بوت تجريبي من BotFather"
export TELEGRAM_WEBHOOK_SECRET="سر_عشوائي"
```

- [ ] استخدم `ngrok` أو `cloudflared` لعمل نفق مؤقت للسيرفر المحلي.
- [ ] سجّل الـ webhook عند Telegram بالرابط الناتج من النفق.
- [ ] ابعت رسالة فعلية من موبايلك للبوت واتأكد إن الرد وصلك.
- [ ] ابعت رسالتين متتاليتين وتأكد إن الذاكرة شغالة برضو على Telegram (زي المرحلة 3).
- [ ] **مهم:** بعد الاختبار، امسح الـ `TELEGRAM_BOT_TOKEN` من أي terminal history أو ملف لو كتبته مؤقتاً.

## المرحلة 8 (اختياري): اختبار تحت ضغط بسيط

لو حابب تتأكد من ثبات السيرفر تحت حمل بسيط قبل العرض:
```bash
for i in $(seq 1 20); do
  curl -s -X POST http://localhost:9090/api/chat \
    -H "Content-Type: application/json" \
    -d "{\"message\": \"إزاي أتابع الأوردر؟\", \"session_id\": \"load_test_$i\"}" &
done
wait
```
تأكد إن السيرفر ماوقعش وكل الطلبات اترد عليها.
